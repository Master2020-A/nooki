Arquitectura del compilador

El compilador de Nooki está escrito en C++20 y es una cadena de traducción ahead-of-time: toma archivos .oki y produce un ejecutable nativo apoyándose en un compilador de C del sistema (gcc, clang o MSVC) como backend.

Esta página da la visión de conjunto: cómo fluye la compilación, cómo se reparte el código dentro de compilador/ y qué hace cada fase. El detalle de cada una está en su página.

El flujo de compilación

Todo va en una dirección, sin idas y venidas: el fuente en texto pasa por análisis léxico, análisis sintáctico, verificación semántica, generación de C y, por último, compilación nativa a través del conductor.

.oki  →  léxico  →  sintáctico (AST)  →  semántico  →  C  →  binario nativo

Ese orden importa porque cada fase puede rechazar el programa: el léxico se queja de un carácter que no existe, el sintáctico de una llave sin cerrar, el semántico de un tipo que no encaja o de un valor que se usó después de moverse. Cuanto antes se detecta, mejor es el mensaje: el compilador nunca genera C de un programa que no ha verificado.

Las fases, una a una

Léxico

Convierte el texto UTF-8 en una secuencia de tokens. Se encarga de los identificadores con tilde, de las secuencias de escape de los textos, de los números y de llevar la línea y la columna de cada token, que es lo que después permite señalar el error exacto.

Sintáctico y AST

Con un analizador Pratt construye el árbol de sintaxis abstracta. La precedencia de operadores está en la tabla del analizador, no repartida por el código, y el árbol se puede volcar con nooki ast para depurar.

Verificador semántico

Recorre el árbol con ámbitos: comprueba que los nombres existan, que los tipos encajen, que las llamadas tengan la aridad correcta, que los campos estén, que el coincide cubra todos los casos y que la propiedad se respete (movimientos y préstamos). Aquí es donde se emite la mayor parte de los diagnósticos NOK3xxx, NOK4xxx y NOK5xxx.

Generador de C

Traduce el árbol a C legible, con un preludio de runtime (textos, vectores, mapas, cajas, aritmética comprobada) y los runtimes de interfaz e inteligencia artificial cuando el programa los usa. El C generado se puede conservar para inspeccionarlo.

Conductor

Orquesta lo anterior: resuelve los módulos (usar), localiza el compilador de C del sistema —o el que diga NOOKI_CC—, lanza la compilación y devuelve el binario o el error con su código de salida.

Cómo se reparte el código

El repositorio se organiza por fases, no por capas genéricas: lexico/, sintactico/, semantico/, generador/ y conductor/, cada una con su prueba unitaria en compilador/pruebas/. Alrededor están diagnostico/ (los códigos, los mensajes y su presentación), cli/ (las órdenes), lsp/ (el servidor de lenguaje) y ui/ e ia/ (los runtimes nativos).
