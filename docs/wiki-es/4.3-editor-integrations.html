Integración con los editores

La carpeta editores/ reúne las extensiones y definiciones que dan a los archivos .oki resaltado, tokenización, emparejamiento de llaves y conexión con el servidor de lenguaje en VS Code, Vim y Neovim, los IDE de JetBrains y cualquier editor que entienda TextMate.

1. TextMate y Visual Studio Code

Nooki usa una gramática canónica de TextMate (source.nooki) para el resaltado en VS Code, Sublime Text, TextMate y Zed. Las reglas están en JSON, en editores/vscode/syntaxes/nooki.tmLanguage.json, y cada una asigna expresiones regulares y conjuntos de palabras a un ámbito de TextMate. Las secciones principales:

  • comentarios: de línea (//) y de bloque (/* … */).
  • texto_multilinea: los textos entre comillas triples (""").
  • textos: los de comillas dobles, con sus secuencias de escape.
  • numeros: flotantes, enteros hexadecimales (0x…) y enteros con guiones bajos opcionales.
  • declaraciones: funcion, variable, constante, clase, estructura, rasgo, enumeracion, tipo y modulo, capturando además el nombre que las sigue.

2. Vim y Neovim

El resaltado en Vim se hace con archivos propios. La detección del tipo de archivo la hace editores/vim/ftdetect/nooki.vim:

au BufRead,BufNewFile *.oki set filetype=nooki

Las reglas están en editores/vim/syntax/nooki.vim, que distingue mayúsculas de minúsculas (syntax case match) y asigna grupos de resaltado:

  • nookiComentario va a Comment;
  • nookiTexto y nookiCaracter a String;
  • nookiDeclaracion agrupa variable, constante, funcion, clase, estructura y rasgo en Statement;
  • y hay patrones contextuales que reconocen la definición de una función (nookiFuncion) y de un tipo (nookiTipoDefinido) mirando la palabra que sigue a la declaración.

3. El plugin de JetBrains

Para los IDE de JetBrains —IntelliJ IDEA, PyCharm, CLion, RustRover— hay un plugin nativo en editores/jetbrains/plugin/. Algunas distribuciones (RustRover 2026.1, por ejemplo) no traen soporte de TextMate, así que la integración es un lexer propio en Java, no una gramática prestada.

Tokens y lexer

  • NookiTokens: define los tipos de elemento (comentarios, literales, palabras reservadas, operadores, identificadores) y asigna cada palabra del lenguaje a su categoría.
  • NookiLexer: extiende LexerBase y tokeniza a mano. Mira el contexto —por ejemplo, si un identificador viene detrás de funcion o de clase— para darle el tipo semántico correcto sin construir un árbol PSI completo.

Colores y configuración

  • NookiSyntaxHighlighter: traduce cada tipo de token a una clave de atributos de IntelliJ, de modo que el color sale del esquema del IDE.
  • NookiColorPage: añade la página de ajustes para cambiar los colores de Nooki en Ajustes → Editor → Esquema de colores → Nooki.

4. El servidor de lenguaje en cualquier editor

Además del resaltado, cualquier editor que sepa hablar LSP puede conectarse a nooki lsp y obtener diagnósticos en vivo, autocompletado y formateo. Esa es la vía para los editores que no tienen gramática propia: basta con decirles el comando y el tipo de archivo.
