Sistema de tipos

El sistema de tipos de Nooki da tipado estático con inferencia, memoria segura, abstracciones sin coste, tipos algebraicos, clases y estructuras, rasgos y genéricos. Esta página recoge las definiciones normativas de la especificación y cómo las implementa el verificador semántico (compilador/incluir/nooki/semantico/tipos.hpp).

Tipos primitivos

Nooki define un conjunto de tipos primitivos que cubre enteros, números en coma flotante, booleanos, caracteres Unicode, texto en el montón, el valor vacío y un entero del tamaño de un puntero. Son entero, flotante, booleano, caracter, texto, vacio y nulo.

Tipos compuestos

  • Colecciones: Vector<T> para listas que crecen y Mapa<K, V> para tablas hash. Hoy el vector admite entero, flotante, texto y estructuras propias sin campos con dueño; el mapa admite como valor entero, flotante o texto.
  • Caja: Caja<T> guarda un valor en el montón y es la pieza con la que se explica la propiedad: una caja tiene un solo dueño y se presta para dejar que otros la lean.
  • Resultado: resultado<T, E> para lo que puede salir bien con T o fallar con E, y opcional<T> para lo que puede no estar.

Clases y estructuras

Nooki distingue dos formas de agrupar datos, y la diferencia importa:

  • clase: tipo con identidad, herencia (hereda), despacho virtual, rasgos (implementa), constructor y destructor, y propiedades.
  • estructura: tipo por valor, que se copia al asignarlo y al pasarlo. Es lo que se usa para un registro de datos: un punto, una ficha, una medida.

Rasgos y genéricos

Un rasgo define un contrato: un conjunto de firmas que un tipo se compromete a implementar. Con eso, una función puede aceptar &Rasgo y despachar al método del tipo concreto que llegue en cada llamada.

rasgo Describible {
    funcion describir() -> texto
}

clase persona implementa Describible {
    publico nombre: texto

    publico funcion describir() -> texto {
        retornar "persona " + este.nombre
    }
}

Los genéricos permiten escribir tipos y funciones parametrizados, de modo que un algoritmo o una estructura de datos sirvan para varios tipos sin renunciar a la comprobación estática.

Cómo representa el compilador los tipos

El verificador semántico modela los tipos con la enumeración nooki::semantico::Tipo y dos funciones de utilidad, nombre(Tipo) y desde_nombre(std::string_view), que traducen entre el nombre que se escribe y el valor interno:

enum class Tipo : unsigned char {
    Desconocido,
    Vacio,
    Entero,
    Texto,
    Booleano,
    Flotante,
};

Los tipos propios (clases, estructuras, enumeraciones) no viven en esa enumeración: el verificador los resuelve por nombre contra la tabla de tipos del programa, y por eso puede decir «falta el campo y» o «punto no tiene miembro z» con el nombre que escribió el programador.
