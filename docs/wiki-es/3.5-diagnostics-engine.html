Motor de diagnósticos

El subsistema de diagnósticos (fuente/diagnostico/) se encarga de llevar la cuenta de los archivos fuente (GestorFuentes), de recoger los mensajes de error y aviso (Emisor), de mantener el catálogo normativo (catalogo.cpp y codigos.hpp) y de presentar la salida de dos maneras: para una persona —texto con color y el fragmento del fuente— o para una herramienta —JSON—.

Arquitectura

El motor es el puente entre las fases del compilador —léxico, sintáctico, semántica y generador— y quien lee el mensaje. Cada una de esas fases no escribe texto libre: emite un código y unos parámetros, y el motor decide cómo se presenta.

El catálogo de códigos

Según la especificación (§11.1), todo diagnóstico lleva un identificador estable con la forma NOK más cuatro dígitos. Los códigos **no cambian** entre versiones del compilador, porque de eso depende que las herramientas externas y las pruebas puedan reconocerlos.

  • NOK0xxx: uso del compilador y entrada y salida de archivos.
  • NOK1xxx: análisis léxico (palabra con tilde, texto sin cerrar, escape desconocido).
  • NOK2xxx: análisis sintáctico (delimitador sin cerrar, token inesperado, falta principal).
  • NOK3xxx: símbolos y ligaduras (nombre no declarado, módulo no encontrado, puntero fuera de inseguro).
  • NOK4xxx: sistema de tipos y comprobaciones (tipo incompatible, coincide no exhaustivo).
  • NOK5xxx: propiedad, préstamos y memoria (uso tras mover, préstamo mutable no exclusivo, préstamo que escapa).
  • NOK6xxx: generación de código y enlace (no hay compilador de C, el compilador de C falló).

GestorFuentes y Emisor

  • GestorFuentes: guarda los búferes de los archivos que se van cargando, asigna a cada ruta un identificador y sabe traducir una posición a línea y columna para poder dibujar el fragmento.
  • Emisor: recoge los diagnósticos según el compilador avanza por las fases, consulta el catálogo y rellena la plantilla del mensaje con sus parámetros ({archivo}, {nombre}, {esperado}…).

Presentación: texto o JSON

Los mensajes existen en español y en inglés (las dos cadenas están en el catálogo), y la salida cambia según la orden o según quién pregunte:

  • Texto para personas: con color cuando la terminal lo admite, el fragmento del fuente, la línea culpable y los acentos (^^^) bajo el fragmento exacto, más el código y la explicación.
  • JSON: para el servidor de lenguaje y para las herramientas, con el código, la ubicación y los parámetros por separado.

Esa separación —código, ubicación y parámetros por un lado; presentación por otro— es lo que permite que la misma comprobación sirva para el terminal, para el editor y para una prueba automática sin duplicar el mensaje en tres sitios.
