Biblioteca estándar y runtimes

Visión de conjunto de la biblioteca de Nooki —módulos escritos en Nooki e incrustados en el propio binario del compilador— y de los runtimes nativos en C que sostienen la inteligencia artificial, el tratamiento de datos y la interfaz de escritorio.

Los módulos de la biblioteca

La biblioteca son varios módulos .oki incrustados que dan los tipos y las utilidades básicas: resultado para lo que puede fallar, textos para manipular cadenas, listas para operar sobre vectores de números, matematicas para la aritmética habitual, fechas para el calendario, archivo para leer y escribir archivos y csv para datos tabulares.

Como están incrustados, un usar los resuelve sin que exista el archivo: no hay nada que copiar ni que pueda faltar en una instalación.

Colecciones: Vector y Mapa

Las colecciones genéricas se apoyan en estructuras del runtime con tamaño dinámico y semántica de propiedad. Vector<T> gestiona un búfer contiguo en el montón; Mapa<K, V> usa hash FNV-1a para indexar las claves con rapidez. Las dos se integran con el verificador para que la propiedad de los elementos sea correcta: sin dobles liberaciones ni uso después de liberar.

El vector admite hoy entero, flotante, texto y estructuras propias sin campos con dueño; el mapa admite entero, flotante y texto como valor.

Inteligencia artificial y datos

Este subsistema une la sintaxis de Nooki con la ejecución nativa a través de runtime_ia.cpp. Expone una API de manejadores que cubre tensores, diferenciación automática (autograd), arquitecturas de red (redes), datos tabulares (tabla), rutinas estadísticas y procesamiento de lenguaje natural (pln).

La forma de usarla es siempre la misma: se crea un manejador, se le dan datos, se entrena y se consulta; y se libera al final. El runtime esconde la reserva de memoria y la aritmética, y el generador solo emite ese C cuando el programa lo usa.

Interfaz de escritorio

La interfaz se apoya en runtime_ui.cpp, que ofrece una capa portable sobre Win32 y X11. Sostiene los módulos de ventana (ventana), disposición (diseno), controles interactivos (controles), accesibilidad (accesibilidad) e imágenes (imagenes), y todo se maneja con un bucle de eventos.

En Linux hace falta libx11-dev para compilar un programa con ventana, y para ejecutarlo sin pantalla se usa xvfb-run. En macOS compila, pero todavía no abre ventana de forma nativa.
