Errores, código inseguro y FFI

Esta página reúne cuatro fronteras del lenguaje: cómo se trata lo que puede fallar (resultado y ?), qué ocurre cuando algo irrecuperable se rompe (los pánicos y el código de salida 70), dónde se puede bajar al metal (inseguro, los punteros y asm!) y cómo se habla con C y desde C (externo y @exportar).

Propagar errores: resultado y ?

Nooki no tiene excepciones. Lo que puede fallar devuelve un resultado, que es una enumeración de la biblioteca estándar —no un tipo mágico del compilador, por decisión del ADR-025—:

publico enumeracion resultado {
    Ok(valor: entero)
    Error(mensaje: texto)
}

Y el operador ? es azúcar para propagar. En lugar de emparejar con coincide en cada llamada que puede fallar, se pone ? detrás de la expresión: si el valor es un Ok, se desempaqueta; si es un Error, se devuelve ese error tal cual desde la función en la que estamos.

La comprobación es estructural: sirve cualquier enumeración cuya primera variante lleve un solo campo. Por eso una biblioteca puede definir su propio tipo de resultado sin pedirle permiso al compilador.

Pánicos y el código 70

Cuando ocurre algo irrecuperable —un índice fuera de rango, una aserción que falla, una división imposible—, el programa aborta: el runtime escribe el diagnóstico por la salida de error y termina con el código 70 (EX_SOFTWARE), que es la convención de los sistemas para «fallo interno del programa». Quien llama a un programa de Nooki desde un guion puede distinguir así un error controlado (código devuelto por principal) de un fallo no controlado.

inseguro, punteros y asm!

Fuera de un bloque inseguro el lenguaje mantiene sus invariantes: la aritmética está comprobada y un desbordamiento de entero es un pánico, no un valor negativo sorpresa.

inseguro es la escotilla explícita. Dentro se puede:

  • hacer aritmética sin comprobar;
  • pedir memoria con reservar, liberarla con liberar, leer y escribir en ella con leer_en y escribir_en, y construir un puntero a una dirección concreta con desde_direccion —que es como se habla con un registro del hardware—;
  • insertar ensamblador con asm!.

Las tres cosas están restringidas al bloque, y no por estilo: asm! fuera de inseguro es NOK3012, y usar los punteros fuera es NOK3013. Así, quien lee el código sabe exactamente dónde se rompen las garantías, y el compilador se lo recuerda.

Hablar con C

Traer funciones de C: externo

Una función que vive en una biblioteca de C se declara con externo:

externo funcion puts(cadena: &texto) -> booleano
externo funcion time(zona: &entero) -> entero

Los tipos se traducen solos: un &texto llega a C como const char*, y un puntero crudo o un valor ausente se representa con nulo.

Exponer funciones a C: @exportar

Al revés también funciona: una función de Nooki marcada con @exportar se emite en el C generado con enlace externo y sin deformación del nombre, de modo que un programa en C puede llamarla.
