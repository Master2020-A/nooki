Colecciones: Vector y Mapa

Esta página describe cómo se representan las colecciones genéricas de Nooki —Vector<T> y Mapa<K, V>— en el compilador y en el runtime: qué estructura de C les corresponde, quién es dueño de sus elementos, cómo se gestiona la memoria y cómo se indexan las claves.

1. La representación en el runtime

En el lenguaje, las colecciones son tipos genéricos parametrizados por el tipo del elemento o del valor. Como el backend es C estándar, cada instanciación se convierte en una estructura concreta del preludio. La traducción se hace en una sola función, tipo_c, y según los parámetros sale una estructura u otra:

En NookiEn C
Vector<texto>nooki_vector_texto
Vector<flotante>nooki_vector_flotante
Vector<entero>nooki_vector_entero
Vector<MiEstructura>nooki_vector_MiEstructura, generado
Mapa<texto, entero>nooki_mapa_texto_entero
Mapa<texto, flotante>nooki_mapa_texto_flotante
Mapa<texto, texto>nooki_mapa_texto_texto

El caso del vector de estructuras es distinto: como cada estructura tiene sus campos, el generador emite un vector a medida para cada una que se use en el programa, con su agregar, obtener, modificar, largo, vaciar y soltar.

2. Propiedad de los elementos

Las colecciones gestionan el ciclo de vida de lo que guardan, y la regla cambia según el tipo:

  • Claves de un mapa: se pasan por referencia (&) y el mapa guarda su propia copia. Así la variable que usaste sigue siendo tuya y no hay movimiento ni liberación sorpresa.
  • Valores de un mapa: también se copian; al actualizar una clave o al quitarla, el mapa libera el valor viejo, que es donde este tipo de estructura suele romperse.
  • Elementos de un vector: el vector se queda con el valor. Meter un texto en un vector lo mueve, y usar la variable después es NOK5001.
  • Leer de una colección: obtener devuelve una vista para los textos —el dato sigue siendo de la colección—, y el valor para los números y las estructuras.

Las tres redes de decisión se comprueban con casos de conformidad: 0063-mapa, 0080-mapa-flotante, 0084-mapa-texto y 0085-vector-estructura.

3. El hash de las claves

Los mapas indexan con FNV-1a sobre los bytes del texto de la clave, con encadenamiento para las colisiones y un rehash al superar el 75 % de ocupación. Es la combinación que da un reparto razonable con muy poco código y sin dependencias.

4. Lo que todavía no hay

Un vector de una estructura con campos con dueño (texto, Vector, Mapa o Caja) no está admitido: exigiría copia y liberación profundas. El compilador lo dice con claridad (NOK6003) en lugar de generar algo que se rompa en ejecución.
