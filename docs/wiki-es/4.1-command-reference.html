Las órdenes de la línea de comandos

Esta página documenta la interfaz de órdenes del compilador: el despacho en cli/orden.cpp y los manejadores de cada orden en fuente/cli/. La interfaz es el punto de entrada para quien usa el compilador: convierte los argumentos en operaciones —construir un proyecto, probarlo, verificar sin compilar, formatear o generar documentación—.

El registro de órdenes

Todo gira alrededor de una tabla central en cli/comandos.hpp. La estructura Comando guarda el nombre, el resumen y el sprint en el que está disponible: un sprint igual a cero significa que la orden está lista para usarse.

struct Comando {
    std::string_view nombre;
    std::string_view resumen;
    int sprint;

    [[nodiscard]] constexpr bool disponible() const noexcept { return sprint == 0; }
};

La tabla COMANDOS enumera todas las órdenes: ayuda, version, compilar, ejecutar, ast, construir, lsp, nuevo, probar, limpiar, verificar, formatear y documentar.

Despacho y sugerencias

La función ejecutar recibe el vector de argumentos. Si viene vacío, imprime la ayuda; si no, busca el primer token en la tabla de órdenes.

Y cuando se escribe una orden que no existe, el despachador calcula la distancia de edición con distancia_edicion() y propone la orden válida más parecida antes de salir con el código de uso incorrecto. Es la diferencia entre un nooki construi que dice «¿querías decir construir?» y un «orden desconocida» que obliga a buscar.

Órdenes de proyecto

Las órdenes de proyecto —nuevo, construir, probar, limpiar— manejan la estructura de carpetas, el manifiesto nooki.toml y los flujos de validación locales. Están en cli/proyecto.cpp y cli/compilar.cpp.

nooki nuevo

Crea el árbol mínimo: un principal.oki de entrada, una carpeta biblioteca/ para los módulos propios y un nooki.toml. El manifiesto se escribe con nooki::escribir_manifiesto.

nooki construir

Busca principal.oki en la raíz de la carpeta o dentro de fuente/, carga el manifiesto con nooki::leer_manifiesto y añade a la búsqueda de módulos las rutas que declara (Manifiesto::rutas_de_busqueda()), que es lo que hace que las dependencias locales se encuentren.

nooki probar y nooki limpiar

  • nooki probar: recorre pruebas/, compila cada prueba, la ejecuta, captura su salida y la compara con su archivo .esperado (normalizando los retornos de carro para que el resultado sea el mismo en Windows y en Linux).
  • nooki limpiar: borra de forma recursiva lo generado (build/, artefactos/) sin tocar el código fuente.

Órdenes de compilación y mantenimiento

El resto de órdenes dan acceso directo a las fases y a las herramientas:

  • compilar: genera el binario, y con sus opciones conserva el C intermedio (--emitir-c) o solo verifica.
  • ejecutar: compila y lanza el programa en un paso.
  • verificar: pasa las fases sin generar binario; es lo que usan las pruebas de los ejemplos.
  • ast: vuelca el árbol de sintaxis, para depurar.
  • formatear: reescribe el fuente con el estilo canónico, o solo comprueba con --comprobar.
  • documentar: genera la referencia de la biblioteca a partir del propio compilador.
  • lsp: arranca el servidor de lenguaje para el editor.
