Generador de código C

El generador (EmisorC), en fuente/generador/generador_c.cpp, traduce el árbol ya verificado a C estándar y portable. Ese C se compila después con la cadena de C del sistema hasta un ejecutable autónomo. El subsistema se encarga de bajar los tipos a C, del runtime que va en el preludio, de la instanciación de genéricos, de las tablas virtuales de los rasgos, de la aritmética comprobada y de la liberación de recursos por ámbito.

Cómo fluye

Toma los nodos que le deja la fase semántica, resuelve los ámbitos, traduce las construcciones del lenguaje y las restricciones de tipo a construcciones equivalentes de C, y pega el preludio del runtime delante del todo. El resultado es un archivo .c legible, que se puede conservar para inspeccionarlo.

El preludio y el mapa de tipos

El preludio define las piezas de C que el programa necesita: el texto con dueño (nooki_texto), las colecciones (nooki_vector_entero, nooki_vector_texto, nooki_vector_flotante, los tres mapas), las cajas (nooki_caja), los punteros (nooki_puntero), la aritmética comprobada y las funciones de archivo y de entrada.

La bajada de tipos está centralizada en una sola función, tipo_c(std::string_view), que evalúa los modificadores de préstamo, detecta los rasgos y traduce los primitivos:

Genéricos y tablas virtuales

Los genéricos y los rasgos se resuelven por especialización de código y punteros gordos. Cuando un tipo o una referencia implica un rasgo, el generador emite una estructura de referencia de rasgo (nooki_ref_<Rasgo>) que empareja el puntero a los datos con el puntero a la tabla de métodos virtuales.

Los contenedores se monomorfizan: Vector<T> y Mapa<K, V> se convierten en estructuras concretas de C según sus parámetros, y en el caso de las estructuras propias se genera un vector nuevo por cada una. La función elemento_de_vector extrae el tipo del elemento a partir del nombre ya transformado, que es lo que permite que obtener y el bucle para devuelvan el tipo correcto.

Aritmética comprobada y liberación por ámbito

Las operaciones aritméticas se emiten con patrones seguros: una suma que desborda no da un valor sorprendente, da un pánico. La comprobación se puede desactivar dentro de inseguro.

La memoria va atada a los ámbitos. Lo que se crea dentro de un bloque —variables con dueño, cajas, colecciones— se anota y se libera al salir, con las llamadas de destrucción correspondientes. Eso es lo que permite tener la comodidad de un lenguaje con recolector sin tener recolector: el programador no escribe la liberación, pero el compilador sí sabe dónde va.
